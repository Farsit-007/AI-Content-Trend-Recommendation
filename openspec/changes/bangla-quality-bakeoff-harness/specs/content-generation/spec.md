## ADDED Requirements

### Requirement: Bangla Quality Bake-off Harness
The system SHALL provide an offline harness that generates content for a configurable matrix of
candidate models, topics, and formats using the same style-pack resolution, style example
retrieval, facts-then-write grounding, and per-format prompt instructions as the live generation
service — differing only in which model id is used per call. The harness SHALL NOT alter serving
configuration or any stored data, SHALL cap the matrix to at most 4 models, 8 topics, and 2 formats
per run, SHALL execute generations serially, and SHALL record a per-cell failure without aborting
the rest of the run.

#### Scenario: Matrix run produces bounded, complete output despite a partial failure
- **WHEN** the harness runs with 2 models, 3 topics, and 2 formats and one candidate model errors on one cell
- **THEN** the run completes, the JSON output contains all 12 cells with the failing cell recorded as an error rather than an output, and no other cell is affected

#### Scenario: Matrix size is capped
- **WHEN** the harness is invoked with 5 candidate models
- **THEN** the run is rejected before any generation call is made

### Requirement: Blinded, Shuffled Review Output
The harness SHALL emit a human-reviewable document in which every sample is labeled without
revealing which model produced it, in an order that does not correlate with model identity, and
SHALL separately emit a machine-readable record mapping each label back to its model, topic, format,
prompt, and output for later analysis. The review document SHALL present a fixed scoring rubric for
every sample.

#### Scenario: Review labels carry no model identity
- **WHEN** a run's review document is generated
- **THEN** no sample's label or surrounding text in the review document names or implies the model that produced it, while the accompanying JSON record maps every label to its true model

#### Scenario: Same run, same seed, same order
- **WHEN** the harness is run twice with an explicit, identical seed and identical inputs
- **THEN** both runs produce the same shuffled sample order

### Requirement: Production Prompt-Assembly Fidelity
Prompts generated by the harness for a given team-less topic/format/style-pack combination SHALL be
constructed via the same style-context and message-building functions used by the live
`POST /content/generate` request path, so that equivalent inputs (same topic, format, resolved
style pack, and absent brand-voice examples) produce identical prompts.

#### Scenario: Harness and live service agree on style-conditioned prompts
- **WHEN** the harness builds a prompt for a topic/format against a resolved style pack, and a live generation request is made for a team with zero brand-voice examples using the same topic, format, and style pack
- **THEN** the two resulting system prompts are identical
